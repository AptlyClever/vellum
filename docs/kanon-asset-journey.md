# Kanon example — Vellum Asset Journey

The Asset Journey is a working leaf-level example for Kanon's theme and page-composition authority. It is not a second page system and it does not make Vellum depend on Kanon being available.

## What Vellum implements

- The local Journey remains a complete, evidence-backed fallback.
- A valid Kanon design snapshot supplies semantic `--ca-*` tokens, expression attributes, recipes, and branding.
- A valid composition for `#/assets/:asset_id` can arrange six real app-owned slots. Vellum renders Kanon's governed layout, content, data, link, and slot node vocabulary and falls back atomically when a document is invalid or requires an undeclared capability.
- `vellum.asset.journey` resolves to the same API read model used by the fallback. Kanon controls composition; Vellum retains asset truth, file access, actions, and destination evidence.
- Runtime evidence uses the shared `data-kanon-release-id`, `data-kanon-composition-id`, `data-kanon-composition-revision`, `data-kanon-render-status`, and `data-kanon-fallback-reason` attributes.

The checked-in [`kanon-asset-journey.composition.json`](kanon-asset-journey.composition.json) is a directly authorable baseline for Kanon Page Studio. It names every slot Vellum actually implements and nothing speculative.

In an embedded Page Studio preview the same document also reveals a **Kanon contract lens**. That authoring-only panel exercises governed text, a live `vellum.asset.journey` metric strip, an observed `vellum.assets.detail` link, and `visible_when` behavior. It is omitted from the production route, where the six product-owned slots preserve the measured reference composition. This gives Kanon a real multi-capability example without making explanatory scaffolding part of Vellum's customer-facing page.

## Personality contract

Kanon supplies the durable semantic foundation. Vellum samples the real marketplace reference already stored in its vault and derives a restrained five-color asset palette for accents, progress connections, and output-card details. If pixel sampling is unavailable, the page uses a safe Fireworks palette. The asset palette never changes evidence state or substitutes for Kanon's semantic text, surface, focus, type, density, motion, and recipe authority.

This is the example Kanon should generalize: governed fleet semantics plus a product-owned, content-responsive expression layer—not generic fleet chrome pasted over every leaf.

## Reference translation

The two selected Fleet-session references are binding for composition and behavior, not for invented asset content. Vellum translates them with the real `fireworks-vol-1-niagara` evidence:

- expanded and hidden rail states retain the same content rather than changing the page;
- marketplace source and validated factory output form the dominant side-by-side transformation band;
- the five-stage provenance rail remains readable in one glance;
- eight validated, visually distinct systems provide the visible payoff;
- destinations show delivery truth, including the Bandit consumer receipt, without implying unobserved Hails or Proscenium delivery;
- asset-derived accents carry Fireworks' color energy while semantic surfaces, type, focus, status, density, and motion remain Kanon-owned.

## What this should teach Kanon

1. A theme authority needs a first-class Games variant. Until one exists, delivering a generic light theme is worse than preserving a leaf's canonical Games expression.
2. A composition authority must arrange app-owned regions without taking ownership of product evidence or forcing the app to become unavailable when a document is absent or invalid.
3. Page Studio needs to show both the production composition and authoring-only contract evidence so route, data, link, visibility, and slot capabilities can be reviewed together.
4. Capability observation should be refreshable after deploy and should surface whether an app's declared route and slots have actually been bound in a released composition.
5. Content-responsive expression belongs beside semantic fleet tokens: Kanon governs durable meaning; the leaf may derive restrained accents from the real content it is presenting.

## Acceptance evidence

The example is complete only when all of the following are true:

- the checked-in document validates against Kanon's current `PageCompositionDefinition`;
- Vellum's manifest, validator, renderer, and checked-in document agree on routes, sources, links, slots, field formats, visibility conditions, and supported node properties;
- no-Kanon, invalid-document, and invalid-token cases leave the complete local page intact and report a precise fallback reason;
- the valid production document renders all six slots with release, composition, revision, and render-status evidence;
- the embedded document reveals the contract lens without adding it to the production route;
- expanded, hidden-navigation, and mobile states pass browser and visual comparison against the selected references;
- the deployed press page is verified against real API rows and media before the Control Alt session is closed.
